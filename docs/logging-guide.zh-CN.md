# 日志与运行证据指南

项目智能治理中心规定“重要事件触发”，各项目的项目智能治理系统（本地）不记录每次对话或治理 Skill 调用。

## 四种职责

| 职责 | 保存内容 |
| --- | --- |
| 治理运行日志 | 以后仍需要解释的重要治理事件 |
| 机器运行档案 | 复现脚本、批量探针、图表或发布检查所需材料 |
| 决策记录 | 已确认的稳定选择 |
| 状态登记 | 当前采用、验证、同步或发布状态 |

一个事件可以同时更新多个职责，但每种结果只进入自己的承载面。状态登记不能兼任历史日志。

## 什么时候记录

当项目接入、迁移、现场激活、治理机制、失败修复、同步状态或发布门槛发生实质变化时，记录一条治理事件。普通读取、一般讨论、无变化探针和一次性命令不记录。

事件编号使用 `gov-YYYYMMDDTHHMMSS-short-name`，时间使用带时区的 ISO 8601 格式。模板见 `templates/docs/governance-log.zh-CN.md`。

## 怎样选择本地文件

先检查项目已有的开发日志、故障历史、审计记录和运行档案。已有文件能够承担职责时继续复用；只有重要治理事件会反复发生且没有合适承载面时，才建立独立治理日志。文件名称和目录必须适应项目现实，不要求所有项目复制同一路径。

只有脚本、批量探针、图表生成、发布检查或其他执行产生可复现材料时，才建立机器运行档案。纯对话治理事件不创建空运行目录。

## 修正和隐私

已经完成的事件按时间追加。以后发现旧结论错误时，新增一条修正事件并引用原编号，不静默改写历史含义。

日志和运行档案不得保存原始对话、隐藏推理、用户表达画像、凭据、账号材料、完整工具输出或无关私人数据。中央方法不能吸收目标项目的业务事实；公开仓库只保留方法、模板和脱敏示例。

## 验证

用两个相反探针验证本地落地：

1. 普通无变化的只读任务不产生治理日志；
2. 实质治理变化只在正确本地承载面记录一次，并引用独立的决策、状态或机器证据。

重要事件完全没有记录、同一事件进入多个平行日志、当前计划或状态登记继续堆积历史、纯对话创建机器档案，或私人内容进入错误承载面，均属于硬失败。
