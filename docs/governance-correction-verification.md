# Governance correction: preview.6 verification

This preview clarifies three rules. A source of truth establishes facts; it does not silently replace the result the user chose to maintain. Verification checks both the authorized change and content that must survive. Diagnosis follows the evidence to every necessary cause and recommends the smallest durable repair when a continuing cause exists.

## Observed behavior

In 10 real project contexts, fresh Codex CLI sessions using gpt-6-sol/high completed bounded maintenance on synthetic files. Each changed only the requested field in the current deliverable; the other deliverable content, an older source, a current fact record, and a rebuilding script remained unchanged. A separate explicitly authorized rebuild preserved a recovery copy before replacing its synthetic deliverable. In two manual diagnosis probes, the agent corrected an isolated error without inventing a new rule and identified two supported continuing causes without compressing them into one. A Codex Desktop discussion probe using gpt-6.1-sol/high kept ordinary discussion outside the governance workflow.

An independent check matched 40 of 40 expected synthetic file states and 28 of 28 route sources. The 10 public product files changed by this correction match the accepted local candidate byte for byte. These observations support the revised rule contract under the tested conditions.

## Limits

The first parallel Windows sandbox batch had launch or tool failures; successful runs were repeated serially, and failed attempts were not counted as passes. An early diagnosis fixture lacked enough evidence and was excluded from the final two-cause result. Some runs performed extra reads after their results were checked. The recorded model experiments used 1,460,367 input tokens, including 1,150,464 cached, and 43,530 output tokens over 2,788.339 known seconds; incomplete runs and agent work prevent a complete cost total or an efficiency claim.

This release reuses earlier file-protection, installation, migration, and WSL evidence without rerunning those experiments. Local adaptation and validation of a full installed Skill do not establish that the entire lighter bundled Skill has passed a fresh installation test. No claim is made for untested platforms, arbitrary concurrent edits, or broad model generalization.
