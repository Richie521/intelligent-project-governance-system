# Daily file protection: preview.5 verification

preview.5: the new behavior passed acceptance under the stated conditions. The manifest and checksum identify the release package. This report covers the new preview.5 daily protection behavior. The preview.4 three-flow scope stays in the [historical report](three-flow-verification.md).

## Evidence obtained

Before ordinary maintenance changes important material, the agent establishes recovery for the complete task-start content, reuses verified recovery points and makes a byte-identical project-local copy only when needed. Older points, relative paths, encoding and line endings are retained. Read-only, unchanged and reliably reproducible temporary outputs avoid extra copies. Committed, uncommitted and untracked Git content are judged separately.

Native Windows independent sessions covered ordinary and continuous maintenance, holdout and same-named sibling recovery, existing recovery points and dirty/untracked Git content. The development suite completed 28 to 35 day maintenance, restored the 28-day original in the next session, and restored the sibling archive in a third session, retaining current files. Two migration-target sessions, with the source inaccessible, completed 21 to 28 day maintenance and exact 21-day recovery in the next session. Complete successful evidence includes exit 0, current-thread usage, `gpt-6.1-sol/high`, effective entry adoption, no added Skill/memory/Hook and byte checks.

A real backup-write denial caused the agent to stop before overwriting and left the original unchanged. A denied link-target read caused it to stop with the external file unchanged and link retained. This proves safe stopping under actual refusal, not proactive recognition of every link boundary.

Three successful Ubuntu WSL sessions covered installation, later-material maintenance and fresh-session recovery with exact-byte checks. The entry and effective instruction chain were both 4049 UTF-8 bytes; later original BOM, CRLF and other content were retained. WSL and native Windows results remain separate.

## Failures and support limits

First failures are retained and classified as product, facility or host issues; attempts without completed receipts or usage are not passes. One development model run completed successfully but its wrapper failed printing Chinese; its saved current-thread evidence and bytes recovered acceptance without another model request. An older migration wrapper remains incomplete same-session artifact evidence; later independent maintenance and recovery have separate completed evidence.

These are bounded synthetic checks. Proactive recognition of every junction, host conversation handoff, macOS, arbitrary concurrent atomic protection, long-term reliability and comparative token/quality gains remain unverified. The rules are agent instructions, not system-level interception, and recovery must not overwrite later work. Earlier diagnosis changes retain their original bytes and evidence scope; this round does not elevate them.
