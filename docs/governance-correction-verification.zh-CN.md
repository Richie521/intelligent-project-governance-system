# 治理纠偏：preview.6 验证

本预览版明确三条规则：来源权威用于判断事实，不能顺手替换用户选定的维护成果；验收同时核对获准变化与应保留内容；诊断依据证据说明全部必要原因，有持续成因时选择能够防止复发的最小修复。

## 已观察的行为

在 10 个实际项目上下文中，全新 Codex CLI 会话使用 gpt-6-sol/high 对合成资料完成限定维护。每次只改当前交付件中指定的字段，交付件其他内容、旧源码、当前事实记录与重建脚本保持不变。另一个明确授权重建的正例先保存恢复副本，再替换合成交付件。两个人工诊断探针分别确认：孤立错误任务内纠正后不强造新规则；两个有证据的持续成因均被识别，没有被压成唯一根因。一次使用 gpt-6.1-sol/high 的 Codex Desktop 普通讨论探针没有误入治理流程。

独立检查核对了 40/40 个预期合成文件状态和 28/28 个路由来源。本轮公开产品文件中受影响的 10 项与已验收候选逐字节一致。这些证据支持列明条件下的规则契约。

## 限制

首次并行 Windows 沙箱批次出现启动或工具失败；成功运行改为串行完成，失败没有计作通过。首版双原因夹具证据不足，未计入最终结果。部分运行在结果已核对后仍有额外读取。已取得的模型实验共输入 1,460,367 tokens，其中缓存 1,150,464，输出 43,530，已知运行时长 2,788.339 秒；未完成运行与代理工作无法合成完整成本，也不能据此声称效率收益。

本轮复用以前的资料保护、安装、迁移与 WSL 证据，没有重跑这些实验。本地适配及完整已安装 Skill 的验收，不等于轻量公开包整套安装重新通过。未验证的平台、任意并发编辑与其他模型不在本报告结论内。
