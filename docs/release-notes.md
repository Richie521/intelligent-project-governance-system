# preview.6 release notes

This preview clarifies how agents preserve the result a user chose to maintain while using source records to establish facts. Verification now checks both the requested edit and content that must remain. Manual diagnosis follows supported causes and recommends only the durable repair needed to prevent recurrence.

Fresh CLI sessions completed bounded synthetic maintenance in 10 actual project contexts; independent checks matched 40/40 expected file states and 28/28 route sources. An authorized rebuild, isolated-error diagnosis, two-cause diagnosis, and an ordinary Desktop discussion were checked separately. See the [preview.6 verification report](https://github.com/Richie521/intelligent-project-governance-system/blob/v0.1.0-preview.6/docs/governance-correction-verification.md) for conditions and limits. Earlier protection, installation, and migration evidence was reused without rerunning those experiments.

# preview.5 release notes

Daily protection joins basic adoption: before ordinary maintenance, the agent establishes recoverable complete task-start content, reuses verified recovery points and creates byte-identical copies only when needed, retaining older points. Read-only, unchanged and reliably reproducible work avoids extra copies.

Native Windows continuous maintenance, independent same-named file recovery, dirty/untracked Git protection, fresh-session maintenance/recovery after migration, and three WSL sessions have byte-level evidence. Safe stopping under real backup denial and denied link reads is verified. Proactive recognition of every link, host handoff, macOS, arbitrary concurrent atomic protection and token/quality gains remain unverified.
