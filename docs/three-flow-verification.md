# Three-Flow Acceptance (v0.1.0-preview.4 Release Candidate)

[简体中文](three-flow-verification.zh-CN.md)

All three flows have completed acceptance under the synthetic materials and host conditions below. This report records the preview.4 candidate checks; check the release page for the published asset and its download verification. The flows are lightweight new-project adoption, organizing an existing project in place, and selectively moving an existing project to a separate new folder. Simplification concerns material and structure, not business-logic refactoring.

| Flow | Verified chain | Boundary |
| --- | --- | --- |
| New project | The frozen installer created only the necessary entry in a native-Windows synthetic project; a fresh conversation read it and completed ordinary work. An unrelated read-only task did not load history, diagnosis or a transaction | This proves the lightweight path for that project and host, without enabling unselected capabilities |
| In-place organization | Windows holdout material covered multiple files, genuine multi-turn user messages, actual cursor pagination, later corrections, decisions versus current configuration, and incremental updates after source changes. Business originals kept their hashes. A fresh desktop Sol high conversation used organized material, while old-conversation continuation checked the current entry | Missing original messages remain gaps, never verified from summaries; a command working directory is not the host-attached project root |
| Move to a new folder | Native-Windows holdout and English WSL chains covered planning, selective copies, path repair, independent target operation, repeat runs and undo that preserves later edits. After real v5 interruptions, fresh target conversations on both hosts verified the same-package installer contract and completed the entry without running project scripts. A separate explicitly authorized task ran the quote tool from the target with the old source path unavailable and obtained 24, with source and target hashes checked | These results prove dependencies for the tested small projects. Switching an older desktop conversation's host attachment remains unproven; start a fresh conversation in the new folder |

A move preserves the old project and stops at unrelated content in a first-run target instead of overwriting or silently merging it. The target source index records the approved scope, same-package installer identity, created files and final hashes. Recovery removes only registered content that still matches and preserves the index by default. Excluded historical material may have an explicit source citation; the new entry must not retain a required relative route to a missing target path. Installation and interruption recovery perform non-executing file checks. Moving or retaining a capability does not authorize running project scripts or services; a current explicit user authorization is required for that runtime check.

The first failures remain in the evidence. An early receipt lived only in the old conversation's answer, so a fresh conversation could not safely undo the move. On v3, denial of index writes produced a competing addendum and an entry missing eight core principles. A writable v4 recovery then ran the quote script without authorization and retained a stale notes/ route. The minimal changes were in both migration guides: persist and verify the same-package installer contract, stop when the original index cannot be updated, retain only target-applicable old rules, and separate runtime authorization from file migration. Focused v5 Windows and WSL recovery turns did not run scripts and generated complete entries with valid routes; only separately authorized ordinary-work turns executed the tool. Existing-file writes across isolated Windows conversations required a writable target. The evaluator adjusted ACLs only on the synthetic target; the package does not repair arbitrary permissions.

Evidence is reused by version impact: unchanged v3 operation, repeat-run and undo results are not relabeled as entirely new v5 runs; v4 tested the real interruption and two package hashes; only the two migration guides changed in v5, which received focused Windows and WSL checks for execution authority and stale routes. Eight desktop Sol high conversations have separate host traces. The 44 unique Windows CLI Sol high turns took 7181.527 seconds; 37 returned known usage of 6,959,892 input tokens (5,922,176 cached) and 302,618 output tokens. Usage for seven interrupted or facility-failed turns is unavailable, not zero. Seven v3, three v4 and five v5 WSL cases are counted separately. These figures are not a bill or evidence of a quality or token benefit over work without this system.

Tests did not expand the earlier basic-adoption authorization for three real projects, scan their private history or move business material. Basic installation requires no preinstalled Skill, Git, Python, Hook or transaction runner; evaluator tools are not user dependencies. macOS, arbitrary permission and link combinations, long-term reliability and all external dependencies remain unverified. Release acceptance also depends on independent privacy review of the public file list, proposed Git refs, tags and attachments, plus manifest/hash and link checks and a fresh GitHub download/readback.
