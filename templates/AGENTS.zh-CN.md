# 项目规则

本项目采用项目智能治理中心的方法，并运行项目智能治理系统（本地）。

治理文件正文权威语言：`zh-CN`（简体中文）。

公共治理文件固定使用 `docs/00-主题地图.md`、`docs/01-来源权威.md`、`docs/02-上下文管理.md` 和 `docs/04-治理日志.md`；`03` 槽位已停用，不创建或维护计划事项投影。按月或分域保存日志时，`04` 只做稳定入口，不复制事件正文。业务文档从 `10` 起使用项目自己的编号区间；人读文件名主体尽量不超过六个汉字，同系列使用短后缀，一级子目录使用三位编号，二级历史或归档子目录使用四位编号。

本声明只控制供人阅读的治理文件和项目入口，不因单轮对话使用另一种语言而切换。生态约定文件名、代码标识、命令参数和机器接口可以保留英文；不得批量翻译业务文档、代码、供应商文件、运行产物或历史快照。

说明本项目用于什么、不用于什么，以及哪些文件或系统不在智能体默认范围内。

## 读取规则

从本文件开始。任务路由不清楚时读取 `docs/00-主题地图.md`。

统一用词默认不启用。只有用户明确同意时，才在这里声明启用并指定现有专题文档或确有必要的项目用词表作为承载面。未启用项目不增加声明、承载面、空表或探针。启用后，新对话在本入口后读取承载面一次，上下文压缩后再读取一次；同一上下文只在承载面变化或任务涉及命名和实质用词时刷新。无害简称和可唯一纠正的语音输入静默统一，只有会改变含义、决定、验证或持久命名的差异才提醒，用户确认后才写回。

只根据用户最新指示确定并完成当前任务。不得读取或使用已停用计划文件作为任务路由、恢复来源或执行依据；历史计划材料仅保留为历史证据。

只有主动启用可选治理运行时的项目才使用事务路径。这些项目在回合收尾根据对话判断是否发生实质治理事件或已获授权的状态变化。没有变化时，不读取运行清单或投影文件，也不调用治理工具；发生变化时，只提交获准的有效投影。当前任务已经明确投影、目标承载面和授权类型时，使用轻量运行路径，不加载 `$project-governance`、Memory、主题地图或完整验证文档。只有精确操作需要当前原文时才预读一次目标，随后只调用一次 `apply`，以终端回执作为统一验证和唯一写回结论。

中央方法变化默认先讨论本地适配。用户明确以“在治理中心修复”授权跨项目同步时，本项目只适配同一治理修复，不把它扩展为业务工作或采用状态授权。采用治理运行时的项目必须在本地请求中声明 `contract_tags: ["central_repair_sync"]`。未接入运行时的项目不得伪造事务回执。

普通纠正直接在当前任务处理。只有用户明确发出“启动分层诊断”等专门命令才进入人工分层诊断；普通纠正和治理讨论不会触发。结构性治理使用 `$project-governance`，已明确投影和授权的事务执行不使用；公开发布或发布就绪检查不进入本地治理路由。

使用最小有效上下文。除非当前任务需要证据，不读取日志、生成产物、缓存、私密笔记或历史交接。

涉及实质治理事件时，从 `docs/04-治理日志.md` 路由到当前项目实际日志承载面。

## 来源边界

只有来源权威尚不明确或存在冲突时，读取 `docs/01-来源权威.md` 判断；已知目标及其职责时直接读取目标，不预读来源说明。对话、记忆、旧笔记和报告在稳定价值写入正确项目文件前都只是证据。

用户最新指示高于旧计划和助手摘要。历史计划材料不能覆盖当前请求。

## 日常资料维护

开始维护文件时，根据实际用途判断它是否承载长期成果、覆盖是否会丢失需要保留的内容；后续新资料同样适用，用户无须预先登记或另发备份命令。默认保护每次独立维护任务开始前的版本，任务内中间编辑按实际风险判断，不机械备份每次工具写入。优先复用项目已声明、可核实且覆盖当前完整内容的恢复办法；有 Git 不等于当前内容已保存，未提交和未跟踪内容须单独判断。缺少可靠办法时，首次需要保护才在项目内 `.backups/<恢复点>/<原相对路径>` 保存原样副本，已有合适位置则沿用；保留旧恢复点，不覆盖旧版本，完整保留内容、编码和换行，使新会话能对应原文件及任务前状态。只写索引、摘要或“已备份”声明不算保护。已获授权的维护可直接完成必要本地备份；额外范围、外部存储或实质资料取舍才确认。只读、无变化或可可靠重建的临时产物不创建多余备份，已有可靠恢复点不重复复制；新资料不自动触发全库整理、治理日志、事务或治理 Skill。备份或恢复失败、权限拒绝或发现并发变化时停止受影响覆盖，报告实际状态；恢复先核对后来编辑，可将旧内容恢复到单独检查文件，不覆盖他人后来成果。这是智能体执行约定，不承诺机器强制拦截或任意外部编辑下的原子保护。

## 人读 Markdown 排版

普通治理段落和列表续行保持同一物理行，不按固定列宽在未结束的句子或语义短语中硬换行。代码块、公式、表格、引用块、显式硬换行和空行分段按原结构保留。修改治理 Markdown 后，收尾前运行治理 Markdown 检查器。

## 写回

任务收尾报告一种写回结果：

```text
Writeback: none
Writeback: updated <path>
Writeback: deferred because <reason>
```

只有结果改变未来路由、权威、验证、安全、决定或复发诊断时才写入长期文件。优先复用职责合适的现有文件；已获执行授权、职责和路径明确且不改变权威、隐私或长期结构时，可以新建聚焦专题并同步更新主题地图。高影响变化先确认，讨论阶段推迟写回，一次性内容不建长期文件。

稳定决定、开放问题和治理事件应写入各自职责对应的文件。只有实质治理事件才记日志；普通读取、一般讨论、无变化探针和每次技能调用不记录。机器证据、稳定决定和当前状态分别保存在各自承载面。
