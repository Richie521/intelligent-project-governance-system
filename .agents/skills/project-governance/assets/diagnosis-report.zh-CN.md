# 诊断报告

仅在用户专门启动分层诊断后使用。下面是可选的简短框架，不要求逐层状态表；按实际因果关系合并或省略小节。

## 问题与原因

用具体事实说明哪一步错了、依据是什么、持续的规则或程序是否会让同类错误再次发生。必要时说明多个成因怎样共同作用；没有检查的层级不作结论。

## 具体修复

写明应修正的现有文件或程序入口、改法，以及为什么改完不会再出现同类错误。修改位置按再次出错的原因选择，可以不同于本次失误的位置。孤立错误经当前任务纠正和验证后，不强造持久规则。若尚待授权，给用户可审查的具体修改和影响。

## 验证

写明已经做过或准备做的同类实际检查、观察结果和限制。涉及构建或发布的路径，在实际适用条件下检查旧内容不会再次出现。未运行的检查不得写成已通过。
